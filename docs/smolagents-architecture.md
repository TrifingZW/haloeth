# smolagents 组成部分解析

> [!NOTE]
> smolagents 由十二个职责单一、契约明确的组成部分构成：消息模型、模型抽象、工具契约、执行器、记忆、编排循环、提示词模板、运行时状态、监控、类型与错误体系、序列化与分发、界面与集成；其中编排循环是唯一的状态机，其余部分均以可替换组件的形式向其提供能力。

## 1. 设计定位

smolagents 是一个**最小抽象**（Minimal Abstraction）的**代理框架**（Agent Framework），其设计主张可归纳为三条：

1. 核心逻辑规模受限，抽象层数保持在原始代码之上最薄的一层。
2. **代码即动作**（Code-as-Action）为一等公民：代理以可执行代码表达动作，而非仅被用于生成代码；出于安全考虑，支持在**沙箱**（Sandbox）环境中执行。
3. **模型无关**（Model-Agnostic）、**模态无关**（Modality-Agnostic）、**工具无关**（Tool-Agnostic）：模型后端、输入输出模态与工具来源均可替换。

工程层面体现为：无全局单例，全部能力通过构造参数注入；组件之间以显式契约交互；协议（提示词）与实现（代码）解耦。

## 2. 组成部分总览

| 编号 | 组成部分 | 职责 | 对外契约 |
| --- | --- | --- | --- |
| 1 | 消息模型（Message Model） | 统一内部对话表示，并规范化为模型输入 | 消息、角色、内容块、工具调用、流式增量 |
| 2 | 模型抽象（Model Abstraction） | 屏蔽供应商差异，提供生成与流式生成 | 生成接口、工具调用解析、参数组装规则 |
| 3 | 工具契约（Tool Contract） | 声明式描述可被代理调用的能力 | 元数据字段、执行方法、输入输出模式 |
| 4 | 执行器（Executor） | 执行代码动作并返回结构化结果 | 注入工具、注入变量、执行并输出 |
| 5 | 记忆（Memory） | 保存运行过程中的全部步骤 | 步骤序列化、步骤到消息的渲染 |
| 6 | 编排循环（Agent Loop） | 驱动「思考—动作—观测」循环直至终止 | 运行入口、单步执行、上下文构建 |
| 7 | 提示词模板（Prompt Templates） | 定义循环协议与各阶段指令 | 四组模板键、模板完整性约束 |
| 8 | 运行时状态（Runtime State） | 跨步骤保存变量，供代码动作读写 | 键值容器 |
| 9 | 监控（Monitoring） | 计时、**Token**（Token）统计与日志 | 日志级别、指标累计、步骤回调 |
| 10 | 类型与错误体系（Types & Errors） | 输出类型包装与错误分类 | 类型包装三接口、错误族与结构化表示 |
| 11 | 序列化与分发（Serialization & Distribution） | 导出、加载与共享代理定义 | 代理字典、模板文件、工具源码、依赖清单 |
| 12 | 界面与集成（UI & Integrations） | 交互入口与外部能力接入 | Gradio 应用、命令行、**MCP**（Model Context Protocol）、远程执行器 |

依赖方向为单向：编排循环依赖消息模型、模型抽象、工具契约、执行器、记忆、监控与提示词模板；外围部分（11、12）依赖核心，核心不反向依赖外围。

## 3. 逐部分解析

### 3.1 消息模型（Message Model）

职责是提供与供应商无关的内部对话表示，并在发送前完成规范化。

内部构成：

- **角色集合**：用户（User）、助手（Assistant）、系统（System）、工具调用（Tool Call）、工具响应（Tool Response）。后两者为内部角色，不属于任何供应商协议。
- **内容块**：文本块与图像块；内容为块的列表，允许一条消息携带混合模态。
- **工具调用结构**：名称、参数、唯一标识符三元组。
- **流式增量结构**：内容增量、工具调用增量（按索引标识同一调用的分片）、**Token** 用量增量；增量聚合按调用索引合并分片，重建完整工具调用。

规范化规则（发送给模型前执行）：

1. 内部角色映射为供应商角色：工具调用映射为助手，工具响应映射为用户。
2. 连续同角色消息合并：文本块拼接，其他块追加。
3. 图像按 `Base64` 内联或图像地址两种协议编码。
4. 提供纯文本降级模式，将结构化内容压平为单文本块。

该部分是唯一的格式转换层，隔离内部表示与外部协议；新增模型后端不改变内部消息表示。

### 3.2 模型抽象（Model Abstraction）

职责是屏蔽模型供应商差异，向上提供统一生成能力。

内部构成：

- **生成能力**：非流式生成与流式生成两种入口；流式入口产出增量事件序列。
- **工具调用解析**：优先采用供应商原生工具调用字段；当响应仅含文本时，回退为从文本中提取**JSON**（JavaScript Object Notation）片段构造工具调用。
- **参数组装**：按固定优先级合并三方参数——模型默认参数（可覆盖、可删除）、调用方显式参数、特定语义参数（停止序列、响应格式、工具清单与工具选择策略）。
- **兼容性开关**：按模型标识判断是否支持停止序列参数，对不支持该参数的推理类模型自动省略。
- **后端注册表**：维护类名到实现的映射，供反序列化时受限加载。

该部分与工具契约并列，是代理与外部世界交互的两个接口之一。

### 3.3 工具契约（Tool Contract）

职责是以声明式元数据与单一行为方法描述一项可被代理调用的能力。

声明式元数据：

- 名称：合法的标识符，且在代理内唯一。
- 描述：供模型理解工具用途的文本。
- 输入模式：每个输入包含类型与描述，支持可空标记；类型取自受限集合（字符串、布尔、整数、数值、图像、音频、数组、对象、任意、空）。
- 输出类型与输出模式：输出模式用于向模型声明结构化返回。

行为与生命周期：

- 实现单一方法，其形参集合必须与输入模式键集合严格一致，构造期即校验。
- 首次调用时执行惰性初始化，供加载模型等昂贵操作使用。

调用期防线：

- 参数校验：拒绝越界参数名、缺失必填参数、类型不匹配；整数到数值的转换被显式放宽；任意类型为通配。
- 输入输出类型包装：调用时可选择将参数与返回值在原始值与包装类型之间转换。

提示词渲染：提供两种渲染器，分别生成「带类型签名与文档字符串的函数定义」（服务代码动作空间）与「单行描述」（服务工具调用动作空间）。

构造方式：继承声明，或由装饰器依据类型注解与文档字符串自动生成工具类，并保留可序列化源码。

来源扩展：Hub 仓库、Space 服务、LangChain 工具、**MCP** 服务器，均被统一为同一契约。

### 3.4 执行器（Executor）

职责是执行代码动作，并返回结构化结果。抽象契约含三个方法：注入工具、注入变量、执行代码并返回输出。

输出结构包含三项：输出值、执行日志、是否为最终答案。

本地执行器机制：

1. **状态容器**：变量空间为跨步持久的键值字典，是代码动作之间传递数据的唯一通道。
2. **工具表分级**：静态工具表不可被代码赋值覆盖，自定义工具表允许覆盖。
3. **导入白名单**：以基础模块集合与额外授权集合的并集为界，按点分前缀匹配授权；未授权导入在执行期报错。
4. **打印重定向**：打印语句被特判并写入状态容器中的输出缓冲，执行结束后截断为日志字段，与返回值分离。
5. **最终答案拦截**：最终答案工具被替换为抛出不可被通用异常捕获所吞没的专用异常的包装函数，其值即输出值，并置位最终答案标记。
6. **执行超时**：以跨平台方式限制单次执行时长。
7. **错误定位**：解析失败与执行失败均包装为统一解释器错误，附带源码定位与异常类型。

该执行器被明确声明为非安全沙箱；需要隔离时应替换为远程执行器（E2B、Modal、Docker、Blaxel）。

执行器仅服务于代码动作空间；工具调用动作空间不经过执行器。

### 3.5 记忆（Memory）

职责是保存运行过程的完整轨迹，并提供两种导出能力：结构化序列化与对话消息渲染。

步骤类型族及语义：

| 步骤 | 语义 | 消息渲染 |
| --- | --- | --- |
| 系统提示步骤 | 系统指令 | 系统消息；摘要模式下丢弃 |
| 任务步骤 | 用户任务 | 用户消息，含任务图像 |
| 动作步骤 | 一次「思考—动作—观测」 | 助手输出、工具调用描述、观测图像、观测文本、错误与重试提示 |
| 规划步骤 | 计划或计划更新 | 助手计划 + 用户「继续执行」提示 |
| 最终答案步骤 | 终止标记 | 不产生消息 |

动作步骤的字段集合：步号、计时、模型输入消息、工具调用、模型输出、代码动作、观测、错误、动作输出、**Token** 用量、是否为最终答案。

两个渲染模式：

- 正常模式：完整渲染，用于构建模型上下文。
- 摘要模式：丢弃系统提示与规划步骤，用于规划更新的输入与受管代理的汇报。

动作步骤的消息渲染顺序即上下文构建算法，依次为：模型输出 → 工具调用描述 → 观测图像 → 观测文本 → 错误与重试指令。因此上下文构建不需要额外的上下文管理器。

记忆接口：重置（清空步骤但保留系统提示）、全量导出、精简导出（剔除体积最大的模型输入消息）、回放、代码动作拼接。

**回调注册表**（Callback Registry）：按步骤类型及其继承链派发回调，注册回调为外部系统订阅运行过程的标准挂载点，监控指标更新即以动作步骤回调形式接入。

### 3.6 编排循环（Agent Loop）

职责是驱动 **ReAct**（Reasoning and Acting）循环：在目标达成前反复执行「动作（由模型产生）与观测（由环境返回）」的循环。

结构上采用**模板方法**（Template Method）：固定骨架不变，扩展点有两处——系统提示构造与单步执行。两种动作空间（工具调用、代码）即为单步执行的两个实现。

构造期装配顺序固定：

1. 校验提示词模板键完整性。
2. 装配受管代理：注入输入模式与输出类型，使其可作为工具被调用。
3. 装配工具：可并入内置工具集；无条件注入最终答案工具。
4. 校验工具与受管代理名称唯一性。
5. 构造记忆与监控，注册步骤回调。

运行期流程：

```
运行(task)
  ├─ 记录任务；将附加参数注入运行时状态；刷新系统提示；按需重置记忆与监控
  ├─ 写入任务步骤
  ├─ 代码动作空间：向执行器注入变量与工具
  └─ 循环（步号自 1 起，上限为最大步数）
       ├─ 若命中规划间隔（首步或每 N 步）→ 生成规划步骤 → 入记忆
       ├─ 构造动作步骤 → 单步执行
       │    ├─ 构建上下文：记忆逐步骤渲染为消息
       │    ├─ 调用模型（携带停止序列与工具清单）
       │    ├─ 解析动作：工具调用（原生或文本回退）或代码块
       │    ├─ 执行动作 → 观测或错误写回记忆
       │    └─ 产出「动作输出」标记是否为最终答案
       ├─ 错误处置：生成错误直接抛出（实现级错误，不重试）；其余代理错误写入步骤错误字段后进入下一轮（自愈重试）
       └─ 收尾：终结计时、派发回调、动作步骤入记忆、步号递增
  ├─ 步数耗尽 → 追加一次模型调用生成兜底答案
  └─ 产出最终答案步骤
```

关键性质：

- **终止条件唯一**：正常退出仅有「最终答案工具被调用」一条路径，因此系统提示将最终答案声明为唯一收尾方式。
- **错误即观测**：可恢复错误以文本形式回灌上下文，并附带重试提示，驱动模型自我纠正。
- **两种动作空间**：工具调用空间一次模型调用产出一个或多个工具调用，多调用可并行执行、结果按序回写；代码空间一次模型调用产出一个代码块，经解析与修正后交由执行器，观测为执行日志与最终输出的拼接（截断）。
- **流式事件集合**：内容增量、工具调用、动作输出、工具调用结果、工具输出、规划步骤、动作步骤、最终答案步骤，构成外部订阅运行过程的完整事件面。
- **协作式中断**：中断以标志位实现，在循环头部检查。

### 3.7 提示词模板（Prompt Templates）

职责是以文本模板定义循环协议与各阶段指令；模板是唯一不依赖专用接口协议的机制。

四组模板键：

| 组 | 键 | 用途 |
| --- | --- | --- |
| 系统提示 | `system_prompt` | 循环协议、示例、工具清单、自定义指令、规则 |
| 规划 | 初始计划 / 更新前置 / 更新后置 | 首次规划与周期性计划更新 |
| 受管代理 | 任务 / 汇报 | 受管代理的输入包装与结果包装 |
| 最终答案 | 前置 / 后置 | 步数耗尽后的兜底答案生成 |

系统提示的结构为：循环协议说明 → 少量示例（使用虚拟工具）→ 实际工具清单（内嵌工具契约的渲染结果）→ 受管代理清单（可选）→ 自定义指令（可选）→ 编号规则列表。

与循环的耦合点：

- 停止序列为文本标记（观测标记、工具调用标记、代码块闭合标记），用于约束生成边界。
- 模板键集合在构造期被强制校验，缺失即失败，保证协议完整。

### 3.8 运行时状态（Runtime State）

职责是保存跨步骤的变量，独立于消息历史。

- 作为键值容器由运行参数注入（附加参数即变量），并注入执行器供代码动作直接访问。
- 最终答案若为字符串且命中状态键，则被替换为对应状态值。
- 与消息历史分离的意义：数据传递不消耗上下文长度。

### 3.9 监控（Monitoring）

职责是记录与展示运行指标。

内部构成：日志级别阈值（关闭、错误、信息、调试）；计时（起始时间、结束时间、时长）；**Token** 用量（输入、输出、合计，合计由前两者导出）；累计器（步数、耗时序列、**Token** 总量）；可读渲染器（面板、规则线、语法高亮、树形结构）。

挂载点：监控的指标更新函数以动作步骤回调形式注册，即运行指标的采集不侵入循环代码。

### 3.10 类型与错误体系（Types & Errors）

**输出类型包装**：文本、图像、音频三种包装类型，各自提供三个接口——原始值、字符串化、序列化；包装类型在工具调用与最终答案边界处自动转换。

**错误族**：

| 错误类型 | 触发场景 | 可恢复性 |
| --- | --- | --- |
| 解析错误 | 模型输出无法解析为动作 | 可恢复（回灌上下文） |
| 执行错误 | 动作执行失败 | 可恢复（回灌上下文） |
| 工具调用错误 | 工具参数不合法 | 可恢复（执行错误的子类） |
| 工具执行错误 | 工具执行失败 | 可恢复（执行错误的子类） |
| 生成错误 | 模型调用失败 | 不可恢复（直接抛出） |
| 步数耗尽错误 | 达到最大步数 | 触发兜底答案流程 |

每个错误均提供结构化表示（类型名与消息），用于序列化与界面展示。

### 3.11 序列化与分发（Serialization & Distribution）

职责是导出、加载与共享代理定义。

导出内容：代理字典（类名、工具、模型、提示词模板、最大步数、规划间隔、名称、描述、依赖清单）、提示词模板文件、每个工具独立源码文件、依赖清单、可运行的应用入口。

加载与安全约束：

- 反序列化使用类名注册表白名单，仅注册表内的代理类与模型类可被实例化。
- 可执行代码与依赖清单的收集源于工具的源码分析。
- 从 Hub 加载需显式声明信任远程代码。

该部分为可选外围，不参与核心循环。

### 3.12 界面与集成（UI & Integrations）

| 集成 | 定位 |
| --- | --- |
| Gradio 应用 | 交互式图形界面，支持流式输出与多轮对话 |
| 命令行入口 | 参数驱动的单次运行入口 |
| **MCP** 工具集合 | 将外部 MCP 服务器工具纳入同一工具契约 |
| 远程执行器 | 将代码执行迁移至隔离环境（E2B、Modal、Docker、Blaxel） |

定位为可替换外围：界面消费的是流式事件集合，执行器替换不改变编排循环。

## 4. 组成部分之间的数据流

一次完整运行的数据流：

```
任务字符串
  → 记忆（任务步骤）
  → 上下文构建（记忆逐步骤渲染 + 角色映射 + 同角色合并）
  → 模型抽象（生成，携带停止序列与工具清单）
  → 动作解析（工具调用 / 代码块）
  → 工具契约（工具调用路径）或 执行器（代码路径）
  → 观测文本 / 观测图像 / 错误
  → 记忆（动作步骤）
  → 循环直至最终答案
  → 最终答案步骤 → 输出值
```

旁路关系：

- 提示词模板参与系统提示构造，系统提示以系统提示步骤进入记忆。
- 运行时状态注入执行器，并可作为最终答案的引用来源。
- 监控作为动作步骤回调订阅每次动作步骤。
- 工具契约与模型抽象是仅有的两个对外接口：分别面向能力与语言模型。

## 5. 扩展点与替换边界

| 组件 | 替换方式 | 影响范围 |
| --- | --- | --- |
| 模型后端 | 实现生成接口，或配置既有后端 | 无（参数组装与解析规则保持不变） |
| 工具 | 继承契约或由装饰器生成 | 无（提示词渲染与参数校验自动生效） |
| 执行器 | 实现执行器三方法契约 | 仅代码动作空间 |
| 提示词模板 | 提供完整模板键集合 | 循环协议可整体改写 |
| 步骤类型 | 新增记忆步骤子类型 | 需实现序列化与消息渲染两个方法 |
| 回调 | 注册到回调注册表 | 无（不侵入循环） |
| 输出类型包装 | 扩展类型映射 | 工具与最终答案边界 |

## 6. 关键设计约束

1. **单一状态机**：全部流程控制集中于编排循环，其余组件为无状态或仅持有自身数据。
2. **动作空间可替换**：两种动作代理仅差异于单步执行与提示词，循环、记忆、错误处置完全复用。
3. **协议与实现解耦**：循环协议由文本模板与停止序列定义，不依赖供应商专用接口。
4. **错误即观测**：可恢复错误转为上下文文本，是自愈重试的唯一机制。
5. **状态与历史分离**：变量经运行时状态传递，消息历史仅承载对话语义。
6. **上下文按需重建**：摘要模式允许在特定场景（规划更新、受管代理汇报）丢弃低价值步骤。
7. **执行隔离为显式选择**：本地执行器声明自身非沙箱，隔离能力由可替换的远程执行器提供。
8. **加载受白名单约束**：反序列化与远程代码加载均需显式授权。
